# 맛집리스트 기획안 (재방문 인증 중심 + 취향 매칭 공유)

## 1. 핵심 컨셉
> "한 번 가본 집"이 아니라 **"또 간 집"**만 진짜 맛집으로 친다.

- 별점·리뷰 대신 **재방문 횟수**를 신뢰 지표로 사용 → 광고/체험단 리뷰 오염 차단
- 내가 저장한 맛집 데이터가 쌓이면 → **취향이 비슷한 유저**를 찾아서 → 그 사람들의 리스트를 추천/공유

## 2. 사용자 흐름
1. 로그인 (기존 `/auth/*` 카카오·구글·네이버 로그인 재사용)
2. 맛집 저장 — 가게 검색(카카오 로컬 API) → "가고 싶음" 또는 "다녀옴"
3. 방문 인증 — 영수증 사진 / 현장 GPS 체크인
4. 재방문 인증 — 2회차부터 뱃지 단계 상승 (1회 → 2회 "재방문" → 3회+ "단골" → 5회+ "찐단골")
5. 방문마다 짧은 태그 입력 (맛 태그 + 상황 태그, 5초 안에 끝나게)
6. 취향 매칭 — "나랑 입맛 비슷한 사람 TOP N" + 그 사람들의 단골집 중 내가 안 가본 곳 추천
7. 리스트 공유 — "성수 해장 단골 7곳" 같은 큐레이션 리스트 공개/링크 공유/팔로우

## 3. 재방문 인증 방식 (어뷰징 방지 핵심)
| 방식 | 신뢰도 | 비고 |
|---|---|---|
| 영수증 OCR (상호·날짜·금액) | 높음 | 같은 영수증 중복 업로드 해시로 차단 |
| GPS 체크인 (가게 반경 50m, 체류 N분) | 중간 | 웹 Geolocation API, 단독으로는 약함 |
| 수동 기록 | 낮음 | 저장만 되고 "인증" 뱃지는 안 붙음 |

규칙:
- 같은 가게 재방문은 **최소 24시간 간격**이어야 카운트
- 인증된 방문만 매칭/랭킹 계산에 반영
- MVP는 영수증 사진 + GPS 병행, OCR 자동화는 2단계

## 4. 데이터 모델 (초안)
```
users            (기존 auth 테이블 재사용)
places           id, kakao_place_id, name, address, lat, lng, category
visits           id, user_id, place_id, visited_at, proof_type(receipt|gps|manual),
                 proof_hash, verified(bool), tags[], memo
saved_places     user_id, place_id, status(want|visited), visit_count(캐시), first/last_visit
lists            id, owner_id, title, description, visibility(public|link|private)
list_items       list_id, place_id, order, comment
follows          follower_id, followee_id
taste_vectors    user_id, vector(json), updated_at   ← 배치 계산 결과
```

## 5. 취향 유사도 (비슷한 사람 찾기)
위스키 쪽 `shared/whisky-match.js`의 "취향 벡터 + 거리" 방식을 그대로 확장.

**유저 취향 벡터 구성**
- 카테고리 비중: 한식/일식/중식/양식/술집/카페 … (재방문 가중)
- 맛 태그 비중: 매운/짠/담백/달달/기름진/국물 …
- 가격대, 지역(생활권)
- **가중치 = 재방문 횟수** (1회 방문 < 3회 단골이 훨씬 강한 신호)

**유사도 계산**
- MVP: 코사인 유사도 (벡터끼리) + **공통 단골집 Jaccard** 보너스
  - 같은 가게를 둘 다 3회 이상 갔으면 매우 강한 신호
- 공통 방문 가게가 3곳 미만이면 매칭 제외 (데이터 부족)
- 하루 1번 배치로 유저별 TOP 20 유사 유저 미리 계산 → 조회는 캐시

**추천**
- 유사 유저들의 단골집 중 내가 안 가본 곳 → (유사도 × 그 사람 재방문 횟수) 합산 점수 순
- "왜 추천?" 문구: "입맛 87% 비슷한 3명이 모두 3번 이상 간 집"

## 6. 공유 기능
- 리스트 단위 공개 설정 (공개 / 링크만 / 비공개)
- 공유 링크 + OG 이미지 (카카오톡 공유 카드)
- 다른 유저 리스트 "내 리스트로 가져오기" (출처 표시)
- 유저 프로필: 단골집 수, 인증 방문 수, 대표 태그 → "나와 취향 일치율 %" 표시

## 7. 프라이버시
- 방문 **정확한 날짜/시간은 비공개**, 공개는 "N회 방문"만
- GPS 원본 좌표는 인증 후 폐기, 결과(verified)만 저장
- 프로필 기본값: 닉네임만, 위치/생활권은 동 단위까지

## 8. 기술 스택 (현재 사이트 구조 기준)
- 프론트: 기존처럼 정적 HTML 페이지 추가 (`restaurants.html`, `r/list.html` 등)
- 백엔드: 기존 whisky-pipeline 서버의 `/auth/*`, `/api/*`에 라우트 추가
  - `/api/places/search` (카카오 로컬 프록시), `/api/visits`, `/api/lists`, `/api/match`
- 지도: 카카오맵 JS SDK
- 영수증 저장: 오브젝트 스토리지, OCR은 2단계(Clova OCR 등)
- 유사도 배치: 파이프라인에 일 1회 작업 추가

## 9. 단계별 로드맵
**MVP (1단계)**
- [ ] 가게 검색·저장 (want / visited)
- [ ] 방문 기록 + 영수증 사진 or GPS 인증, 재방문 카운트·뱃지
- [ ] 내 맛집 리스트 만들기 + 링크 공유

**2단계 — 매칭**
- [ ] 방문 태그 입력 → 취향 벡터 계산 배치
- [ ] 비슷한 취향 유저 TOP N, 일치율 표시
- [ ] 유사 유저 기반 추천 피드

**3단계 — 커뮤니티**
- [ ] 팔로우, 리스트 가져오기
- [ ] 지역별 "찐단골 랭킹" (재방문 인증 수 기준)
- [ ] 영수증 OCR 자동 인증

## 10. 정해야 할 것
1. 위스키핫 사이트 안의 한 섹션인지, 별도 서비스(도메인)인지
2. 재방문 인증 강도 — 영수증 필수 vs GPS만으로도 인정
3. 초기 콜드스타트 — 가입 시 "자주 가는 집 5곳" 입력받아 바로 매칭할지
4. 위스키 취향 데이터와 연결할지 (예: 위스키바/페어링 맛집)
